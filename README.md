# 품사 시험지 (중학교 1학년 국어)

교사가 문항을 출제하고, 학생이 링크로 응시하면 결과가 Supabase에 쌓이는 웹앱입니다.
**모든 코드가 `index.html` 한 파일**에 들어 있습니다. (빌드 도구 없음)

```
index.html            앱 전체 (교사 화면 + 학생 화면)
supabase/schema.sql   DB 준비용 SQL — Supabase SQL Editor 에서 한 번 실행
```

## 동작 방식
- 그냥 접속하면 → **교사 화면** (로그인 → 출제 → 결과)
- 주소 뒤에 `?quiz=<시험ID>` 가 붙으면 → **학생 화면** (응시 → 제출)
- 학생용 링크는 교사 화면의 "학생 링크 복사" 버튼이 만들어 줍니다.

## 설정
1. **DB**: Supabase 대시보드 → SQL Editor → `supabase/schema.sql` 붙여넣고 Run (한 번만).
2. **키**: `index.html` 상단 `<script>` 안의 `SUPABASE_URL` / `SUPABASE_ANON_KEY` 확인.
   (publishable/anon 키만. secret 키 금지.)
3. **교사 계정**: Supabase → Authentication → Users → Add user → 이메일·비밀번호,
   "Auto Confirm User" 체크.
4. **배포**: 이 저장소를 GitHub Pages 로 켜면 끝. (Settings → Pages → Deploy from a branch → main / root)

## 배포 후 주소
- 교사: `https://<아이디>.github.io/<저장소>/`
- 학생: 교사 화면에서 링크 복사

# 독서 기록 (책갈피 · 서술형 내용 이해 · 토론 질문)

독서논술 수업용 앱입니다. **`reading.html` 한 파일**이고, 품사 시험지와 같은 Supabase 프로젝트를 씁니다.

```
reading.html          독서 기록 앱 (교사 화면 + 학생 화면)
supabase/reading.sql  독서 기록용 DB — SQL Editor 에서 한 번 실행
```

## 바로 체험하기
- `reading.html` 을 더블클릭해서 열면 **체험 모드**로 열립니다 (몽실언니 샘플과 예시 학생 기록이 들어 있음).
- 배포한 주소에서는 끝에 `?demo=1` 을 붙이면 체험 모드입니다.
- 체험 모드의 기록은 그 기기의 브라우저에만 저장됩니다.

## 실제로 쓰기
1. Supabase → SQL Editor → `supabase/reading.sql` 붙여넣고 Run (한 번만).
2. 배포한 주소의 `reading.html` 로 들어가 품사 시험지와 같은 교사 계정으로 로그인합니다.
3. "몽실언니 샘플로 만들기" 또는 "+ 새 책" → 주차·읽을 범위·서술형 문제·예시 답안을 입력하고 저장합니다.
4. "학생 링크 복사" 링크를 학생에게 보냅니다.

## 구조
책 → 주차 → **박스**(교재의 박스 하나) → 줄거리 + 생각하기 문제.
줄거리에서 빈칸이 될 말을 `[대괄호]`로 감싸면 빈칸이 됩니다.

| 쓰는 법 | 뜻 |
|---|---|
| `[태극기]` | 정답과 거의 같으면 맞음 |
| `[김 주사\|새아버지]` | 둘 중 하나와 같으면 맞음 |
| `[댓골로 찾아왔고@댓골,찾아]` | **핵심어** 채점. 쉼표(,)로 나눈 말이 모두 들어 있으면 맞음 |
| `[온갖 일을 시켰고@온갖,일,시키·시켰]` | 가운뎃점(·)으로 나눈 말은 그중 하나만 있으면 됨 (시키고/시켰고 모두 맞음) |

채점 기준: **책 내용이 바뀌었나?** 어미·시제·조사·띄어쓰기만 다르면 맞음, 내용이 빠지거나 틀리거나 책의 핵심 표현을 자기 말로 뭉뚱그리면 다시 쓰기.
시제가 사실을 바꾸는 곳(돌아가셨다 ↔ 돌아가실 것 같다)은 핵심어를 과거형으로 씁니다 (`@돌아가셨·죽었`).
애매한 답은 선생님 화면에서 **인정**을 누르면 맞음이 됩니다.

## 학생 화면
- 이름 입력 → 주차 선택 → **내용 이해 / 나의 책갈피 / 생각하기 (결석했을 때)**
- 내용 이해: 박스 줄거리 속 빈칸을 채웁니다.
  1. 처음 제출 → 칸마다 **맞았는지만** 보입니다 (정답은 안 보임).
  2. 틀린 칸만 책을 다시 찾아 고쳐서 **한 번 더** 제출합니다. 맞은 칸은 그대로 둡니다.
  3. 그래도 틀린 칸에만 정답이 보입니다. 채점은 서버에서 하므로 정답이 미리 학생 기기로 가지 않습니다.
- 책갈피: 마음에 들어온 문장, 쪽수, 고른 까닭, 함께 이야기하고 싶은 것. 친구들 것은 볼 수 없습니다 (발표는 수업에서).
- 생각하기: 결석한 학생 보강용. 평소에는 종이 교재로 수업 시간에 합니다.
- 쓰는 중인 글은 기기에 임시 저장되어, 창을 닫아도 남아 있습니다.

## 교사 화면 (수업 보기)
- **제출 현황**: 학생별 빈칸 맞은 개수 (처음 → 다시), 책갈피·보강 제출 여부
- **내용 이해**: 빈칸마다 처음 답 기준 정답률과 학생별 답 (처음 답 → 다시 쓴 답). 한마디, 확인, **다시 풀게 하기**(그 학생 답 삭제)
- **책갈피**: 함께 이야기하고 싶은 것 + 마음에 들어온 문장. 수업 전 발표 순서·모둠 질문 준비용
- **생각하기 (보강)**: 예시 답안과 학생 답, 한마디

## 한계
- 학생은 로그인 없이 이름으로 구분합니다. 같은 이름을 쓰면 같은 학생으로 처리됩니다.
- 빈칸 "맞음"은 띄어쓰기·문장부호를 빼고 같거나 거의 같을 때만 셉니다. 표현이 다른 답은 선생님이 직접 보세요.
- 학생이 답을 낸 뒤 빈칸·문제 순서를 바꾸면 답이 엉뚱한 칸에 붙습니다. 순서는 처음에 정해 두세요.

## 참고 / 한계 (품사 시험지)
- 학생 응시는 로그인이 없습니다. 중복 제출은 브라우저 저장으로만 막으므로 다른 기기/시크릿 창에서는 다시 제출될 수 있습니다. 결과표에서 확인·정리하세요.
- 정답(`answer`)은 학생에게 전송되지 않습니다. 채점은 DB 함수(`submit_quiz`)가 합니다.
- 시험을 "마감"하면 학생은 응시할 수 없습니다(제출된 결과는 유지).
- 문항 저장 시 해당 시험의 문항은 전체 교체됩니다. 응시가 시작된 뒤에는 문항 순서를 바꾸지 마세요.
